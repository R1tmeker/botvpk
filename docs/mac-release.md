# Выпуск с Mac

Проект с доработками находится в этой папке. Запуск `RELEASE-ON-MAC.command` из обычного Терминала использует отдельную рабочую копию в `.artifacts/mac-release/`; исходная папка сохраняется.

1. При отсутствии GitHub CLI запуск скачает официальный архив `cli/cli` и проверит SHA-256 по официальному файлу контрольных сумм.
2. Если потребуется, откроется авторизация GitHub. Нужен аккаунт с правом записи в `R1tmeker/botvpk` и доступом к GitHub Actions. Для изменения workflow OAuth-авторизация должна иметь право `workflow`; оно запрашивается при первом входе.
3. Загружается актуальный `main`, затем применяется общий патч с трёхсторонним объединением. Конфликт останавливает процесс до отправки. Отправка не использует `--force` и также остановится, если `main` изменится в ходе запуска.
4. Запуск ждёт workflow `deploy.yml`: backend-тесты, frontend-тесты, браузерные проверки, сборка образов и штатное развёртывание с резервными копиями и откатом.
5. После успеха GitHub Actions проверяются серверная версия, readiness, smoke-проверки и состояния контейнеров. При необходимости SSH запросит пароль root. Пароль в файлах проекта не хранится.

Для автоматического развёртывания должны быть настроены секреты существующего workflow: `SERVER_HOST`, `SERVER_USER`, `DEPLOY_PATH` и `SSH_PRIVATE_KEY` либо `SSH_PASSWORD`; при наличии используется `SSH_KNOWN_HOSTS`. Если настройки отсутствуют, workflow остановится и покажет причину. Этот запуск сам не изменяет секреты GitHub и конфигурацию действующего сервера.

Проверка сервера по умолчанию использует `/opt/botvpk`. Если workflow разворачивает в другом каталоге, укажите `BOTVPK_APP_ROOT` при запуске. Имя Docker Compose-проекта — `botvpk`, как в текущих конфигурациях. Проверяются backend, bot, vk_bot, frontend, nginx, PostgreSQL, Redis и ClamAV, включая SHA образов приложения.

Если GitHub отклонит push из-за отсутствия scope `workflow` у уже авторизованного аккаунта, используйте `gh auth refresh -h github.com -s workflow` и повторите запуск. Путь к скачанному `gh` находится в `.artifacts/mac-release/github-cli/binary-path`.

## Что проверено в этой сессии

8 октября 2026: 42 локальные проверки правил ответов, обращений и заявки прошли на Python 3.12. Полный pytest, frontend-сборка и браузерные сценарии в этой сессии не подтверждены. GitHub недоступен из песочницы, а SSH получает `Operation not permitted`; поэтому `main` и сервер в этой сессии не обновлялись. Файл запуска подготовлен для выполнения пользователем в обычном Терминале.

Также прошли шесть сценариев самого запуска на локальном bare-репозитории: успешная отправка, сохранение более новых изменений в `main`, конфликт, ошибка CI, отказ push и ошибка проверки SSH. При конфликтах и отказе push удалённая тестовая ветка не менялась; при ошибке CI проверка SSH не запускалась; при любой ошибке запуск не объявлял выпуск успешным. Синтаксис Bash и встроенных Python-фрагментов проверен. В этих сценариях GitHub CLI и SSH заменены имитациями; они проверяют управление выпуском, а не сетевой доступ или действующий сервер.
