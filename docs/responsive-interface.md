# Адаптация интерфейса

Изменения подготовлены в ветке `codex/responsive-interface` на основе коммита `0907578bb9abd62ee6b74c61ac4c547c1507d7cf`. Все 285 исходных файлов получены с GitHub и сверены по Git SHA. Локальный репозиторий содержит точный исходный коммит; история до него не скачана.

## Компоновка

| Размер | Поведение |
| --- | --- |
| До 599 px | Нижняя навигация, формы в одну колонку, состав в карточках со всеми полями |
| 600–767 px | Более просторные панели, три колонки разделов, окна по центру экрана |
| 768–1023 px | Две колонки карточек расписания, нормативов, материалов и объявлений; сетка сводки |
| От 1024 px | Боковая навигация и рабочая область вместо контейнера шириной 430 px |
| От 1280 px | Четыре колонки разделов и более плотная сетка данных профиля |
| Широкий монитор | Общая ширина ограничена 1360 px для удобного чтения |

Правила компоновки находятся в `frontend/src/screens/App.responsive.scss`. Они подключены в конце CSS-модуля приложения, сохраняют его имена классов и переопределяют прежние конфликтующие мобильные правила. Дополнительные правила есть у входа, графиков, промо, уведомлений и старого Mini App.

## Изменения

- Нижнее меню на телефоне и вертикальное меню на компьютере. Число колонок определяется доступными пользователю пунктами. Активный пункт отмечен `aria-current`.
- Таблица состава на телефоне превращается в карточки с подписями полей. На широком экране остаётся таблицей; её область можно прокручивать клавиатурой.
- Формы, фильтры, группы кнопок, сводки, карточки и длинные строки используют доступную ширину. Прогресс нормативов занимает всю строку сетки.
- Основные кнопки и поля имеют высоту минимум 44 px; на телефоне поля используют шрифт 16 px. Масштабирование страницы разрешено.
- Окна сведений, заявок, политики обработки данных и видео используют общий `Dialog`. Он выводит окно в `document.body`, удерживает фокус, отключает взаимодействие с фоном, закрывается по Escape и возвращает фокус инициатору. Это устраняет зависимость фиксированных окон от анимируемых контейнеров страницы.
- Высота и положение окон учитывают `visualViewport`, безопасные области браузера и Telegram. При открытой клавиатуре на сенсорном устройстве нижняя навигация скрывается.
- Копирование и ссылки в карточке участника доступны с клавиатуры. Добавлена ссылка перехода к содержимому.
- Переключение слайдов приостанавливается при фокусе и наведении. Системная настройка уменьшения движения отключает анимации и автоматическое переключение.
- Старый интерфейс в `miniapp/` также получил широкие сетки и правила для небольших экранов.

## Проверки

В `frontend/tests/e2e/responsive.spec.ts` подготовлены 53 сценария, которые конфигурация `playwright.responsive.config.ts` запускает в Chromium и WebKit. Они проверяют экраны 320×568, 390×844, 844×390, 768×1024, 1280×800 и 1920×1080, обе темы, роли участника и командования, разделы администрирования и профиля, вступление в клуб, карточку участника, изменение размера без перезагрузки и вход на коротком экране.

Сетевые ответы заменены тестовыми данными; проверки не меняют реальные записи. Сценарии проверяют переполнение страницы, размещение навигации, её кнопки, границы окна, управление фокусом и ошибки JavaScript. Скриншоты и трассировки сохраняются в результатах Playwright.

После установки Node.js 22.12 или новее:

```bash
cd frontend
npm ci
npm run test
npm run build
npx playwright install chromium webkit
npm run test:responsive
```

Workflow `.github/workflows/frontend-responsive.yml` выполняет эти проверки на pull request и сохраняет отчёт браузеров. Он не публикует приложение.

## Фактически выполненная проверка

- Синтаксический разбор TypeScript/TSX и конфигураций: без ошибок.
- Строгая проверка типов `Dialog`, `useAppViewport`, `chartUtils`, новых сценариев и конфигурации браузерных проверок: без ошибок. Использованы определения React 18 и Playwright; всё приложение этой проверкой не охвачено.
- Семь SCSS-файлов скомпилированы проверочным компилятором LibSass. Для него локально развёрнут единственный Sass-модуль адаптации и сохранены CSS-функции `min`, `max`, `clamp`. Это подтверждает структуру SCSS, но не заменяет сборку через штатный Dart Sass и Vite.
- `git diff --check`: без ошибок.

Полную сборку, unit-тесты и браузерные сценарии в этой среде выполнить не удалось: npm не имеет сетевого доступа, запуск Chromium и локального сервера запрещён окружением. Запись в GitHub отклонена автоматической проверкой разрешений, поэтому CI не запускался, ветка не опубликована и pull request не создан. Визуальную корректность на реальном устройстве и работу клавиатуры внутри Telegram необходимо подтвердить указанными проверками перед выпуском.
