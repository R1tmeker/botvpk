Архив содержит исходный проект, предыдущую адаптацию интерфейса и новые доработки Telegram-бота, API и приложения. Основной бот — `backend/app/bot.py`, который запускается сервисом `bot` в Docker Compose.

## Дополнительные доработки: заявки, переписка, обучение и сохранение данных

| Раздел | Что улучшено | Как использовать |
| --- | --- | --- |
| Заявка в Telegram | Шесть шагов с отображением текущего шага и итоговой анкетой. Можно вернуться к предыдущему полю и продолжить начатую заявку. | Переписка в Telegram | Собственные обращения доступны по страницам; можно читать историю и отвечать без Mini App. Длинные сообщения разделяются на части, история показывается по три сообщения на странице. | `/myappeals` → обращение → «Ответить»; `/appealview 12` |

| Переписка в приложении | Текст очищается после успешного ответа сервера. При ошибке остаётся в поле; повторная отправка защищена от одновременных нажатий. Каждое обращение имеет отдельный черновик пользователя. | Enter добавляет строку; Ctrl/⌘+Enter отправляет; лимит — 4000 символов |
| Список обращений | Поиск по номеру, теме и описанию, фильтр статусов, сортировка по последнему обновлению. При ошибке загрузки доступны объяснение и повтор. Первоначальное описание видно даже у старых обращений без начального сообщения в истории. | Раздел «Обращения» |
| Уведомления об обращениях | Автор получает уведомление о смене статуса и ответе. Сообщение автора направляется назначенному активному ответственному либо командованию взвода и администраторам. Автор, который сам является командиром, не получает уведомление на собственный ответ. | Уведомления категории «Обращения» с переходом к переписке |
| Обработка обращений | После ответа автора на запрос информации статус «Нужна информация» возвращается в «В работе». Можно повторно открыть решённое обращение; старая дата закрытия сбрасывается. Проверяются статус и права назначаемого ответственного. | Управление обращениями в админке |
| Учебные материалы | Поиск, фильтры изученных/неизученных материалов, счётчик и процент прогресса, следующая неизученная запись. Отметку можно снять. Повторное нажатие не создаёт дубликат в базе. | «Материалы» → «Отметить изученным» / «Продолжить обучение» |
| Управление обучением | Скрытые материалы и курсы остаются доступны в админке для повторной публикации. Новый материал можно включить в курс, добавить текст и перенести между курсами. Несуществующий курс возвращает понятную ошибку проверки. | Админка → «Материалы»: «Курс нового материала» и выбор курса у существующей записи |
| Вложения обращений | Отправка обращения ждёт загрузки вложения. Позднее чтение или загрузка не подставляет удалённый файл. Автозагрузка ждёт восстановления текста черновика, повторные события сети не запускают параллельные загрузки; есть кнопка повтора. | «Прикрепить файл» / «Повторить загрузку вложения» |
| Напоминания об участии | «Пока не знаю» больше не считается окончательным ответом в центре командования. Просроченные и начавшиеся занятия исключены из запроса напоминаний. Счётчик учитывает активный состав и нужное отделение. | Центр командования → запрос ответов |

Черновики сохраняются в IndexedDB. При недоступном или заблокированном хранилище интерфейс продолжает работать с памятью вкладки и прямо предупреждает, что данные не переживут её закрытие. Операции записи и удаления выполняются последовательно: поздняя запись не восстанавливает отправленный черновик. Медленное чтение не перезаписывает новый ввод. Сохранение запускается также при уходе со страницы и скрытии вкладки.

Кэш расписания и материалов используется при сетевых и серверных ошибках. Ответы `401`, `403`, другие ошибки клиента и отменённые запросы больше не подменяются старыми данными. Права на чужие обращения одинаковы в API и боте; массовое назначение ответственного также недоступно командованию отделения. Изменения переписки обновляют обычный раздел и админку через существующий механизм SSE без публикации содержимого сообщений.

| Функция | Что изменилось | Как использовать |
| --- | --- | --- |
| Поиск | Поиск занятий, нормативов, доступных материалов, обращений и, для командования, участников. Кнопки открывают найденную запись в приложении. | `/search тренировка` или кнопка «Поиск» |
| Уведомления | Страницы по шесть записей, общий счётчик непрочитанных, фильтр непрочитанных, просмотр текста и переход в приложение. Открытая запись отмечается прочитанной. | `/notifications`, затем кнопка записи, «Далее» или «Прочитать все» |
| Нормативы | Видны статус последней сдачи и комментарий проверяющего; добавлены кнопки конкретных нормативов. | `/normatives`; для сдачи отправить фото, видео или документ |
| Мои обращения | Последние десять собственных обращений со статусами и кнопками перехода к переписке. | `/myappeals` или «Мои обращения» в меню |
| Расписание | Показывает все семь ближайших занятий, места и сохранённые ответы. Массовая кнопка больше не заменяет сами карточки занятий. Время отображается в часовом поясе клуба из `TZ` / `TIMEZONE`. | `/schedule` |
| Ответ на несколько занятий | «Приду на все» обрабатывает занятия, которым нужен окончательный ответ. Уже сохранённый окончательный ответ проверяется повторно после блокировки записей. | Кнопка под расписанием |
| Изменение ответа | После сохранения остаются кнопки ответа. Причину отсутствия можно выбрать или написать, если справочник пуст. | Кнопки «Приду», «Не приду», «Пока не знаю» |

Исправлены случаи, когда массовый отказ сохранялся без причины, старая кнопка обходила срок ответа, а некорректный ID в кнопке вызывал исключение. Неактивная учётная запись больше не получает внутренние права через свою прежнюю роль. Ввод причины проверяется повторно по текущему пользователю, сроку и занятию; комментарий ограничен 500 символами, как поле базы данных. Команда, введённая вместо причины, не сохраняется как причина отсутствия.

Удалено ошибочное создание немедленного уведомления при ответе «Пока не знаю», которое раньше выдавалось за отложенное напоминание. Ответ остаётся в списке требующих окончательного решения.

## Приложение и сайт

- **Уведомления:** поиск в заголовке и тексте, категории, фильтр непрочитанных, полное содержание, переход к связанной записи и загрузка следующих страниц. Счётчик учитывает весь ящик, а не только первые 50 записей. Ошибку загрузки можно повторить; ошибка сохранения не скрывается.
- **Массовый ответ:** выбрать занятия без окончательного ответа и нажать «Приду на выбранные». За один запрос сохраняется до 50 ответов. Выбор сохраняется при ошибке; во время отправки кнопки блокируются.
- **Расписание:** описание и срок ответа в карточке; «Без ответа» включает «Пока не знаю». Закрытые ответы недоступны в интерфейсе, время проверяется каждые 30 секунд и при возвращении в окно. «Сегодня» определяется часовым поясом клуба.
- **Архив:** загружаются последние 90 дней расписания. Более старое занятие можно открыть по прямой ссылке: приложение запрашивает его отдельно и выбирает вкладку архива.
- **Самоотметка:** занятие остаётся видимым, пока идёт занятие или открыто окно отметки. Кнопка учитывает границы окна, совпадающие с backend: по умолчанию от 15 минут до начала до 20 минут после начала.
- **Работа без сети:** очередь самоотметок разделена по пользователям. При временной ошибке записи сохраняются для повтора; после успешной отправки или окончательного отказа сервера удаляются из очереди. Старые записи без идентификатора пользователя не отправляются от имени другого аккаунта.
- **Причины отсутствия:** выбранная причина, требующая комментария, теперь отправляется вместе с её ID. Текст ограничен 500 символами. Ошибки сервера отображаются с объяснением.
- **Поиск:** отмена устаревших запросов, ограничение длины запроса, состояние ошибки и повтор. Категории результатов чередуются, чтобы совпадения по событиям не вытесняли все остальные результаты.
- **Переходы:** ссылки на занятия, нормативы и материалы выделяют запись и переводят к ней фокус. Ссылка на обращение открывает переписку, на человека — карточку участника. Уведомление о сдаче норматива больше не путает ID сдачи с ID самого норматива.

Предыдущая адаптация сохранена: телефон, планшет и компьютер, боковая навигация на широком экране, карточки состава на телефоне, доступные диалоги, безопасные области Telegram и экранная клавиатура. Подробности — в [docs/responsive-interface.md](docs/responsive-interface.md).

## API и права доступа

- Общая проверка ответов для Telegram и приложения: роль, отделение, отмена занятия, начало, срок, допустимый ответ и активность причины отсутствия. Сохранено право командования отвечать после дедлайна до начала занятия.
- Массовая операция проверяет весь набор перед записью и выполняется одной транзакцией. При недоступном занятии она не сохраняет часть ответов. Записи блокируются в одинаковом порядке; одиночные ответы также используют блокировку занятия.
- Ограничены размер набора и формат ID. Ответы и массовое прочтение записываются в аудит.
- Поиск использует те же аудитории материалов, что раздел обучения. Командир отделения видит в поиске только собственные обращения; чужие обращения доступны с уровня заместителя командира взвода, как в разделе обращений.
- Просмотр расписания не позволяет участнику запросить чужое отделение. Пользователь без отделения видит общие занятия.
- Прочтение уведомлений ограничено их владельцем. Повторное прочтение сохраняет исходное время прочтения. Массовое прочтение выполняется одним SQL-обновлением.
- Изменения ответов и прочтения публикуют события обновления для приложения через существующий механизм Redis/SSE.
- Новые маршруты: `POST /api/schedule/events/respond-bulk` и `GET /api/notifications/summary`. Список уведомлений поддерживает `category`, `q`, `unread_only`, `limit`, `offset`.

Дополнительные маршруты этого этапа: `DELETE /api/learning/materials/{id}/view`, `GET /api/admin/learning/materials` и `GET /api/admin/learning/courses`. Ответы публичного API материалов содержат персональные `is_viewed` и `viewed_at`; прогресс загружается только для текущего профиля.

Новые таблицы, миграции и зависимости не добавлялись. Backend, frontend и бот нужно обновлять вместе, поскольку интерфейс использует новые API-маршруты. Подготовленные изменения находятся в локальной ветке; рабочий сервер не обновлён.
