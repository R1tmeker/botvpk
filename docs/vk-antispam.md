# Доставка VK без повторов

Входящие сообщения с одинаковым ID обрабатываются один раз. Метка хранится в Redis 24 часа и действует между процессами и перезапусками. Для сообщества используется ID сообщения в конкретной беседе; нулевой глобальный ID не считается уникальным. При недоступности Redis работает ограниченный кеш процесса.

Исходящие сообщения бота игнорируются. В групповой беседе подсказка о личных сообщениях появляется только по команде меню, не чаще раза в десять минут. Обычные сообщения участников не запускают ответы бота.

Ответы на входящее событие получают постоянный `random_id`, отдельный для каждого ответа. Если обработка прервалась после отправки и событие повторилось, VK получает прежний идентификатор. Фоновая доставка также использует постоянный ID уведомления. Назначение `random_id` описано в [официальной схеме VK](https://github.com/VKCOM/vk-api-schema/blob/master/messages/methods.json).

Очередь защищена транзакционной блокировкой PostgreSQL, поэтому два процесса не отправляют её одновременно. За проход выбирается одно уведомление на получателя. Обычные уведомления доставляются не чаще одного в минуту, срочные могут пройти раньше, с пределом три в минуту. Ответы на действия пользователя не ждут фоновой очереди.

При ошибке VK следующая попытка выполняется через пять минут. Успешную доставку фиксирует `vk_sent_at`; пропуск устаревшего или повторного автоматического уведомления фиксируют отдельные `vk_suppressed_at` и `vk_suppression_reason`. Пропуск не выдаётся за успешную доставку и не удаляет уведомление из истории приложения. Объявления с вложениями и переписка не объединяются по совпадению текста.

Старые утренние сводки, суточные напоминания без ответа, опросы завершённых и отменённых занятий не отправляются заново. Опрос не приходит участнику, который уже ответил. Повторы автоматических сообщений о той же сущности объединяются; для системных сообщений используется короткое окно создания, чтобы сохранить ежедневные сводки.

Команда «Напомнить участникам» создаёт одну сводку занятий на человека за 24 часа, с датами, местным временем и кнопкой перехода в расписание. Повторные и одновременные нажатия не создают по сообщению на каждое занятие.

Проверки выполняются с подставной отправкой: повторные и одновременные входящие события, сетевой сбой после первого ответа, отключение Redis, сообщения групповой беседы, PostgreSQL-очередь, повтор команды напоминания, история пропущенных уведомлений. Тесты не отправляют сообщения настоящим пользователям.
